# Verified compatibility and build design

Pinned 2026-11-07, choosing a mutually supported stable toolchain rather than requiring the newest SDK:

| Component | Version |
|---|---|
| Java | 17 |
| Gradle | 8.11.1 |
| Android Gradle Plugin | 8.9.2 |
| Kotlin | 2.2.10 |
| Compile / target SDK | 35 |
| Minimum SDK | 26 |
| Build tools | 35.0.0 |
| Node | 22 |

[Official AGP 8.9 compatibility](https://developer.android.com/build/releases/agp-8-9-0-release-notes): Gradle 8.11.1, JDK 17, maximum API 35. [Official Kotlin compatibility](https://kotlinlang.org/docs/gradle-configure-project.html): Kotlin 2.2.0–2.2.10 supports Gradle 7.6.3–8.14 and AGP 7.3.1–8.10.0.

The wrapper was generated by the official Gradle 8.11.1 distribution `wrapper` task in an empty temporary project, then copied intact. The official distribution SHA-256 is pinned in wrapper properties. Generated wrapper comments retain upstream licensing.

The editor build uses exact npm dependency versions plus package-lock.json. Built assets and dependency license notices are committed and checked for drift in CI. Runtime has no INTERNET permission and requires no Node, Python, Termux, server or account.

Native WebView design follows [WebViewAssetLoader](https://developer.android.com/reference/androidx/webkit/WebViewAssetLoader) and [origin-restricted WebMessageListener](https://developer.android.com/reference/androidx/webkit/WebViewCompat.WebMessageListener). Android System WebView must support WEB_MESSAGE_LISTENER; old implementations show an update request, with no insecure bridge fallback.
